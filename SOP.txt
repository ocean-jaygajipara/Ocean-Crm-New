1) SYSTEM OVERVIEW
--------------------------------------------------------------------------------
Ocean CRM = Customer Relationship Management.

Main modules:
  - Login / Dashboard
  - Inquiry (customer inquiries)
  - Masters (statuses, products, locations, sources…)
  - Users + Roles (Admin)
  - Company Settings / DB Sync (Admin)

Technology:
  - PHP + MySQL (XAMPP)
  - Folder : htdocs/Ocean Crm New
  - URL    : http://localhost/Ocean%20Crm%20New/


2) LOGIN FLOW
--------------------------------------------------------------------------------
Page : index.php

Steps:
  1. Username + Password enter
  2. System users table mathi match kare
  3. Session set thay:
       - user_id, username, full_name, role
       - custom_role_id, custom_role_name, role_code
       - permissions (role_permissions mathi)
  4. Redirect → dashboard.php

Login role types (users.role):
  - admin  = full access (permission check skip)
  - hr     = custom role (Sales Person etc.) thi module access
  - employee = portal user (custom role)

Important:
  - Admin always full access.
  - Sales / other users = Custom Role permissions + team data scope.

4) ROLE & PERMISSION FLOW
--------------------------------------------------------------------------------
Admin path:
  Users  → Staff user create/edit
  Roles  → Custom role create + permission matrix

Permission modules (examples):
  - inquiry  (view / add / edit / delete)
  - masters  (view / add / edit / delete)
  - users
  - roles

Sales Person role (default):
  - Inquiry : View + Add + Edit
  - Inquiry Delete : NO
  - Masters / Users / Roles : NO

Kai rite check thay:
  - Function : canAccess('module', 'action')
  - Page guard : requireAccess('inquiry', 'view')
  - Sidebar menu pan permission hisab e show/hide

Flow:
  Login → load role_permissions → session.permissions
       → sidebar + pages permission check
       → allowed modules j open thay


5) TEAM HIERARCHY (REPORTS TO) — IMPORTANT
--------------------------------------------------------------------------------
Concept:
  Manager ne team member ni inquiries pan dekhay.

DB:
  users.reports_to = manager nu user id
  Example:
    JAY.reports_to     = 0     (top)
    RAJ.reports_to     = JAY id
    BHAVIN.reports_to  = JAY id
    HARSH.reports_to   = JAY id

UI ma set karva (Admin):
  1. Admin login
  2. Sidebar → Users
  3. Team member Edit (e.g. BHAVIN)
  4. Field "Reports To" → JAY select
  5. Save

Visibility rule (non-admin):
  User ne inquiry dekhay jo:
    - created_by = pote OR team member
    - OR assign_to = pote OR team member

Meaning:
  - BHAVIN login → only Bhavin nu data
  - JAY login    → Jay + Raj + Bhavin + Harsh nu data
  - Nested team pan support (A → B → C to A ne C pan dekhay)

Code helpers:
  - getUserSubordinateIds()
  - getInquiryScopeUserIds()
  - canAccessInquiryRecord()


6) INQUIRY MODULE — FULL FLOW
--------------------------------------------------------------------------------
Files:
  inquiry/index.php      = List (DataTable)
  inquiry/add.php        = Add form
  inquiry/edit.php       = Edit form
  inquiry/_form.php      = Shared form fields
  inquiry/save.php       = Save
  inquiry/ajax_list.php  = List AJAX data
  inquiry/ajax_status.php= Grid mathi status update
  inquiry/delete.php     = Soft delete
  inquiry/restore.php    = Restore

6.1 Add Inquiry
  1. Inquiry → Add Inquiry (or Dashboard shortcut)
  2. Fill:
       - Inquiry No (Auto / Manual mode)
       - Date, Customer, Company, Phone, Email
       - Country / State / City / Area / Address
       - Requirement Details
       - Product Details (multi rows: Product + Qty + Requirements)
       - Inquiry Status, Follow Up Status, Source
       - Next Follow Up Date
       - Created By / Assign To
  3. Save → inquiries + inquiry_products tables

Created By / Assign To rules:
  - Admin : Created By change kari shake
  - Sales : Created By locked (pote), Assign To select kari shake

6.2 List Inquiry
  - Filters: Search, Country, State, City, Source, Status, Follow Up, Active/Deleted
  - Grid columns: Sr, Inquiry No, Date, Customer, Company, Phone,
                  Location, Source, Inquiry Status, Follow Up, Action
  - Next Follow Up column LIST mathi remove che (form ma field rehse)

6.3 Grid mathi Status Update (inline)
  - Inquiry Status dropdown → change → AJAX save (ajax_status.php)
  - Follow Up Status dropdown → same
  - Permission: inquiry EDIT joiye
  - Toast message aave; fail thay to old value back

6.4 Edit / Delete / Restore
  - Edit pencil → edit.php
  - Delete = soft delete (status=0), Restore possible (delete permission)
  - Non-admin: only scoped records edit/delete
